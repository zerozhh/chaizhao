# evals · 评测基准集

以**误报率 / 漏报率**为核心指标的回归测试集。目的：skill 每次改动后，跑一遍用例，确认「该抓的抓得住、不该抓的不误伤」——后者更重要（裁决纪律：宁可漏报不可错报）。

## 用例文件

`cases.jsonl`——每行一个 JSON 用例：

| 字段 | 含义 |
|---|---|
| `id` | 用例标识 |
| `type` | `positive`（应检出谬误）/ `negative`（应零检出：玩笑、有效推理等） |
| `input` | 被分析文本 |
| `must_find` | **必须**报出的谬误编号（漏报即失败） |
| `optional` | 可报可不报的编号（不计失败；用于置信度处于中/存疑的边缘项） |
| `must_not_flag` | **不得**报出的编号（报出即误报） |
| `notes` | 判定说明 |

## 怎么跑

1. 在**全新会话**中安装并加载 skill（`/chaizhao` 或自然语言触发）
2. 逐条投喂 `input`，收集输出的谬误清单（编号 + 置信度 + 承重标记）
3. 对照用例逐项判定

## 判定指标

| 指标 | 定义 | 及格线 |
|---|---|---|
| **漏报率** | `must_find` 中未报出的比例 | 0%（承重项）／≤1 项（非承重项） |
| **误报率** | 报出了 `must_find ∪ optional` 之外编号的比例；negative 用例报出任何条目即误报 | negative 用例 100% 干净 |
| **定名准确** | 报出编号与 `must_find` 一致，而非同族近似（如把 D4 报成 A1） | 主定名一致，括注近似名可接受 |
| **置信度校准** | 置信度与用例预期档位（高/中）一致 | 允许±一档 |
| **承重标记** | ⚠ 标记落在 `load_bearing` 指定的条目上 | 一致 |

## 用例来源

- `live-*`：真实实测对话（2026-10 会话中产生，含原始判定记录）
- `syn-*`：合成用例，每个对准一个此前实测未覆盖的谬误编号
- `neg-*`：负样本——语域豁免与**有效推理**（防「把 MT 判成 DA」这类形式层误报）
